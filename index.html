About this data

Positions. Positions are zero-based and count only the digits after the decimal point. Position 0 is the first digit after the point (the 1 in 3.1415…); the leading 3 is not counted and is not searched.

What is searchable. Only the digits listed in data/manifest.json. A static website cannot search digits it has not downloaded: each search streams through every data file in the manifest, one file at a time. A "not found" result only means the sequence does not occur in those digits, not that it never occurs in π.

Where the digits come from. The included digits were computed with two independent methods (Chudnovsky binary splitting and the mpmath library); both agreed on every digit before they were written to the JSON files. They are not random and not hand-typed.

Adding more verified digits. Add a file such as data/pi-010.json containing {"start": 1000000, "digits": "…"}, where digits is a string of decimal digits that continues exactly where the previous file ends (digits after the decimal point only, no "3."), and start is the zero-based position of its first digit. Then add {"file": "pi-010.json", "start": 1000000, "length": N} to files in manifest.json and increase totalDigits by N. The page checks that files are contiguous and match their declared lengths, and reports an error otherwise. Only import digits from a trusted, verified source.

Opening locally. Browsers block fetch() of local JSON files when the page is opened via file://. Host the folder on any static host (for example GitHub Pages) or any static file server.
